# Mirrly TG Proxy — Автоматический деплой Cloudflare Worker

Интерактивный инструмент для создания и деплоя персонального Cloudflare Worker для SOCKS5-трафика Telegram. Worker принимает TCP-релей только к разрешённым адресам Telegram по WebSocket; SOCKS5-согласование выполняет само приложение.

---

## Способы запуска

### 1. Двойной клик на Windows (один файл `deploy.bat`)
Достаточно скачать **только один файл** `deploy.bat` и запустить его двойным кликом (весь код и логика уже вшиты внутрь).

### 2. Запуск через PowerShell (Windows)
```powershell
.\deploy.ps1
```

### 3. Запуск одной строкой без скачивания (PowerShell)
```powershell
irm https://raw.githubusercontent.com/joycecurcirt539-dot/Mirrly-TG-Proxy/main/tools/deploy-worker/deploy.ps1 | iex
```

### 4. Запуск на Linux / macOS / WSL (Bash)
```bash
chmod +x deploy.sh
./deploy.sh
```

## Возможности скрипта

* **Интерактивное меню**:
  * `[1]` Быстрое создание воркера со сгенерированным именем в 1 клик.
  * `[2]` Создание воркера с указанным именем.
  * `[3]` **Смена аккаунта Cloudflare**: сброс сессии и вход под другой почтой для обхода суточных лимитов 100 000 запросов бесплатного тарифа.
  * `[4]` **История созданных воркеров**: просмотр всех сгенерированных узлов.
* **Автосохранение в `mirrly_workers.txt`**: скрипт сохраняет дату, имя, публичный домен и прямую ссылку `mirrly://` каждого созданного воркера.
* **Автоматическое копирование**: публичный домен копируется в буфер обмена системы.
* **Автономность**: компактный JS-код SOCKS5-релея со списком разрешённых сетей Telegram и API `cloudflare:sockets` встроен в скрипт.
* **Проверка зависимостей**: при отсутствии Node.js скрипт предложит открыть официальный сайт для установки.

Исходник Worker находится в `worker.js`. После его изменения выполните `node tools/deploy-worker/sync-worker.mjs` из корня репозитория: команда обновит встроенные копии в приложении, документации и скриптах установки.

Новый клиент добавляет `flow=1` к `/tcp-v2`. Worker тогда ограничивает неподтверждённые данные в направлении клиента окном 4 MiB и продолжает чтение Telegram после подтверждения записи в локальный SOCKS5-сокет. Старые клиенты продолжают работать через `/tcp` и обычный `/tcp-v2`.

Цепочка SOCKS5: Telegram → локальный SOCKS5 → MirrlyEngine → WSS/TLS → Worker → TCP → Telegram. Для `/tcp` и `/tcp-v2` с параметром `target` движок использует обычный TLS с проверкой сертификата, без ECH, выбора браузерного TLS-профиля и случайных браузерных HTTP-заголовков. Telegram-данные передаются бинарными WebSocket-сообщениями; payload в заголовках Upgrade не допускается. Обязательное WebSocket masking сохраняется и снимается транспортом Cloudflare до обработки сообщения Worker.

Подтверждение готовности — отдельное сообщение ровно из четырёх байтов: `56 02 00 00` или `56 03 00 00`. Ошибка, закрытие или таймаут ACK не переключают соединение на `/tcp`. Совместимость с `/tcp` включается только после HTTP 404/405/410 от `/tcp-v2`; сетевые ошибки и HTTP 502 не считаются признаком старого протокола. Выбор Worker, Happy Eyeballs, heartbeat и контроль потока остаются активными: эта версия упрощает транспорт, но не является экспериментом с отключением всех механизмов управления.

## Привязка к приложению:
1. Откройте **Mirrly TG Proxy** -> **Менеджер воркеров**.
2. Нажмите **«+ Добавить»** -> Вставьте скопированный домен -> **«Сохранить»**.
3. Нажмите на добавленный воркер для его активации.
