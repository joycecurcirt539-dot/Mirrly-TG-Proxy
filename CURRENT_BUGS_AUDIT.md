# Текущие баги Mirrly TG Proxy

Краткая фиксация пользовательских симптомов. Причины в коде пока не исследовались.

## P0 — Краш при остановке прокси

Статус: исправлено и проверено на устройстве. Фактической причиной повторного падения оказался `tokio::spawn` в MOB-003 `DialBudgetManager.notify_generation_change()`: FFI `SetNetworkGeneration` вызывался с Kotlin-потока без активного Tokio reactor, а release-профиль Rust завершал процесс через `panic=abort`. Смена generation переведена на синхронный reactor-независимый путь; добавлен regression-тест. Rust собран для четырёх ABI, core-тесты и release APK проходят. На устройстве выполнены два цикла запуска/остановки: сервис корректно завершился, процесс приложения остался жив, crash-буфер пуст.

Приложение полностью падает при:

- обычной остановке прокси;
- переключении между MTProto и SOCKS5;
- смене режима аплинка, поскольку для применения нового режима требуется остановка текущего.

Ожидаемый результат: прокси безопасно останавливается и перезапускается, режимы переключаются без падения приложения.

## P1 — Дублирование логов при повторном входе на вкладку

Статус: исправлено в рабочем дереве; история переведена на единый `StateFlow`, повторно прочитанные строки logcat дедуплицируются по исходному событию. Unit-тесты и сборка debug APK проходят. Остаётся ручная проверка повторного входа на вкладку.

При каждом повторном открытии вкладки логов уже показанные записи добавляются заново. В частности, повторяются сообщения про Happy Eyeballs, модуль защиты, DoH Bootstrap и проверку хэша.

Ожидаемый результат: история логов сохраняется без повторного добавления старых записей; новые события появляются один раз и отображаются аккуратно.

## P1 — Ложные уведомления о нестабильной сети

Статус: исправлено в рабочем дереве. Временная потеря Android-флагов `VALIDATED`/`NOT_SUSPENDED` больше не считается подтверждённым обрывом; уведомление о потере сети подавляется при свежем трафике или успешной проверке прокси. Первый выбор маршрута больше не отображается как переключение на резервный. Unit-тесты и компиляция проходят; остаётся ручная проверка уведомлений на устройстве.

При работающем прокси появляются ложные уведомления о нестабильной сети, переподключении или похожих проблемах.

Ожидаемый результат: уведомления отражают реальное состояние соединения и не сигнализируют о сбое при стабильно работающем прокси.

## P2 — Перегруженные и дублирующиеся названия SOCKS5

Статус: исправлено в рабочем дереве. Технические поля маршрута и оператора Cloudflare Worker теперь сводятся единым форматтером к `Cloudflare WSS`: в уведомлении используется короткое название, на главной странице — `Cloudflare WSS · Защищено`. Статусы остальных аплинков не изменены. Unit-тесты и debug-сборка проходят; остаётся ручная визуальная проверка на устройстве.

Проверено в режиме SOCKS5:

- во всплывающих уведомлениях повторяется формулировка вида «Cloudflare Worker WSS — публичный релей / Cloudflare Worker — публичный релей»;
- на главной странице выводится избыточная конструкция вида «Cloudflare Worker WSS — публичный релей (Cloudflare Worker) · публичный релей».

Ожидаемый результат:

- в уведомлении: короткое название «Cloudflare WSS»;
- на главной странице: «Cloudflare WSS · Защищено»;
- без повторов слов «Cloudflare Worker» и «публичный релей».

Поведение этих текстов в остальных режимах пока не проверено.
