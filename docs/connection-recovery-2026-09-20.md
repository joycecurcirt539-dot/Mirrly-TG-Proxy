# Исправление обрывов и восстановления соединений

## Подтверждённые дефекты кода

1. `BridgeActivity` завершал WebSocket-соединение после 20 секунд без кадров.
   Первый heartbeat ping при этом отправляется через 20–60 секунд в зависимости
   от сети, экрана и энергосбережения. Исправное простаивающее соединение могло
   закрыться раньше ping. Убран конкурирующий таймер; решение о потере транспорта
   принимает heartbeat. Предельный простой приложения и завершение после EOF сохранены.
2. Успешные локальные записи обновляли heartbeat как входящие ответы. При загрузке
   медиа это могло откладывать проверку пропавшего обратного канала. Теперь только
   полученные кадры подтверждают доступность другой стороны. Ожидание блокировки
   записи для управляющего кадра входит в его таймаут; отмена прерывает heartbeat.
3. После DISCONNECTED включались флаги dormancy у PingEngine и ActiveLivenessProbe,
   но обработчики возвращения сети их не снимали. Теперь проверки возобновляются
   при смене/возобновлении сети и первичном уведомлении о доступной сети. Watchdog
   восстановления SOCKS5-воркеров также запускается повторно при необходимости.

Первые два исправления относятся к общему WebSocket-транспорту MTProto/SOCKS5.
Третье — к контролю соединения Android. Новый таймер периодического перезапуска
всего прокси не добавлялся; живые соединения при пробуждении проверок сохраняются.

## Проверки

- Rust: `native_heartbeat_contract` и `bridge_lifecycle` с feature
  `heartbeat-test-utils`: 21 тест успешно, включая загрузку без входящих ответов,
  простой до первого ping, частичные кадры, отмену, half-close и передачу данных.
- Kotlin: `NetworkDormancyRecoveryTest`, `NetworkGenerationReadinessContractTest`,
  `PingEngineTest`: 16 тестов успешно.
- Нативные release-библиотеки собраны для arm64-v8a, armeabi-v7a, x86 и x86_64.
- `:app:assembleRelease` успешно. Подпись arm64 APK проверена; SHA-256 встроенного
  движка совпадает с пересобранной библиотекой.
- APK установлен поверх приложения через `192.168.31.170:40183` (`Success`).
  Версия 2.0.0.1 / code 27; время обновления на телефоне 2026-09-20 21:41:17.
  Activity запущена, процесс работает; при проверке сразу после запуска
  ошибок AndroidRuntime/FATAL не обнаружено. Реальная передача медиа не проверялась.

## Проверка в реальном использовании

Для каждого режима (MTProto и SOCKS5): оставить прокси включённым на несколько
минут без трафика, затем отправить крупное видео; повторить после выключения и
включения экрана. Затем проверить потерю и возвращение сети, не перезапуская
прокси. Существующий TCP-поток после реального обрыва не восстанавливается:
клиент должен открыть новое соединение, а прокси — оставаться работоспособным.

Конкретный длительный сбой с телефона в этой сессии не воспроизведён. Тесты
подтверждают устранение перечисленных дефектов, но не исключают отдельный сбой
удалённого воркера, участка воркер–Telegram или другого транспорта. Если зависание
повторится, сохранить журнал до ручного перезапуска и указать время, режим,
аплинк и тип сети.
