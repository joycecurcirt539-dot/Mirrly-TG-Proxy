# Project Guidelines & Release Rules (Mirrly TG Proxy)

## 1. Правила Составления и Оформления Релизов на GitHub
При публикации каждого нового релиза на GitHub для проекта Mirrly TG Proxy **ОБЯЗАТЕЛЬНО** соблюдать следующие стандарты:

1. **Первые строчки релиза (Changelog Summary Preview)**:
   - Релиз должен **СРАЗУ** начинаться с краткой выжимки ключевых изменений без использования заголовка `#` и без вводных слов вроде «# Mirrly TG Proxy — Релиз...» или «В v1.0.9...».
   - Длина выжимки — примерно 5–10 слов. Она извлекается парсером `UpdateChecker` и выводится в компактных Android-уведомлениях (Rich Update Notifications).
2. **Стиль и Тон Текста (Без пафоса и без эмодзи)**:
   - **Строгий и понятный стиль**: Текст должен быть емким и понятным как обычному пользователю (что изменилось в работе приложения), так и разработчику (технические детали, порты, классы, параметры).
   - **Полный запрет на эмодзи**: Запрещено использовать любые эмодзи (символы смайликов, значков и т.д.) в текстах релизов, описаниях изменений и системных диалогах.
   - **Отсутствие пафоса и рекламных штампов**: Категорически запрещены эмоциональные и маркетологические слова (например: «революционный», «невероятный», «флагманский», «магия», «турбо-мощный» и т.п.). Сообщаются исключительно фактические изменения.
   - **Аккуратное оформление**: Использование четких заголовков Markdown (`##`, `###`), маркированных списков, подсписков, выделений кодом для технических терминов (`SOCKS5`, `:10808`, `WSS`, `UpdateChecker`, `SHA-256`) и разделительных линий (`---`).
3. **Публикация только Release APK**:
   - На GitHub в артефакты релиза загружаются **ТОЛЬКО** файлы из папки `release` (публикация `app-debug.apk` запрещена).
4. **Контрольные отпечатки SHA-256 для КАЖДОЙ версии**:
   - Для **КАЖДОЙ** новой версии приложения необходимо рассчитать и опубликовать в секции контрольных сумм отпечатки SHA-256 для **ВСЕХ** сборок пакетов (`app-universal-release.apk`, `app-arm64-v8a-release.apk`, `app-armeabi-v7a-release.apk`, `app-x86_64-release.apk`, `app-x86-release.apk`), а также отпечаток ключа подписи (Keystore SHA-256). Это требуется для валидации целостности пакета встроенным модулем верификации (`UpdateChecker` / `SignatureVerifier`).

## 2. Назначение установочных пакетов (APK)
* **app-universal-release.apk**: Универсальная сборка. Содержит нативные библиотеки под все архитектуры (ARM64, ARMv7, x86, x86_64). Гарантированно подходит для любого Android-устройства. Единый основной файл для автообновлений и публикации.
* **app-arm64-v8a-release.apk**: Сборка ARM64. Оптимизирована для большинства современных смартфонов и планшетов (64-битные процессоры ARM). Обладает меньшим размером.
* **app-armeabi-v7a-release.apk**: Сборка ARMv7. Для старых 32-битных Android-устройств.
* **app-x86_64-release.apk**: Сборка x86_64. Для 64-битных эмуляторов Android (Android Studio, LDPlayer, BlueStacks) и устройств на базах процессоров Intel/AMD.
* **app-x86-release.apk**: Сборка x86. Для 32-битных эмуляторов Android x86.

## 3. Ключевые изменения

### Сетевой стек и протоколы
* **Поддержка SOCKS5 прокси**:
  * Реализован TCP-релей SOCKS5 на локальном порту 10808 для передачи трафика чатов, медиафайлов и звонков.
  * Устранен баг жизненного цикла сокет-слушателя при старте службы.
* **Унифицированное WSS-туннелирование Cloudflare Worker**:
  * Разработан единый протокол туннелирования для режимов MTProto и SOCKS5 через Cloudflare Worker (используется API cloudflare:sockets).
  * Оптимизирована логика переключения сокетов при смене сети (Wi-Fi и LTE).

### Интерфейс и управление
* **Раздельное управление воркерами**:
  * Добавлены независимые переключатели дефолтного воркера для протоколов SOCKS5 и MTProto.
  * Кастомный домен пользователя имеет абсолютный приоритет при туннелировании.
* **Обновленный визуальный стиль**:
  * Переработаны системные диалоги: применен прозрачный стиль с размытием фона и четкими контурами элементов.
  * Убран технический шум с главного экрана в пользу лаконичных статусов состояния.

### Безопасность и верификация
* **Проверка целостности и подписи**:
  * Реализована проверка цифровой подписи APK в нативном C++ NDK слое перед передачей файла в системный инсталлятор.
  * Добавлена автопроверка отпечатка SHA-256 скачанного обновления перед установкой.

## 3. Сборка и Назначение Релизных APK (Release Only)
1. **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** публиковать `debug` версию APK (`app-debug.apk`). Собираем **ТОЛЬКО** релизные версии (`./gradlew assembleRelease`). Использование/создание старого имени `app-release.apk` отменено и удалено.
2. **Файлы установочных пакетов в `app/build/outputs/apk/release/`**:
   - `app-universal-release.apk`: **Универсальная сборка**. Содержит нативные библиотеки под все архитектуры (ARM64, ARMv7, x86, x86_64). Гарантированно подходит для любого Android-устройства. Единый основной файл для автообновлений и публикации.
   - `app-arm64-v8a-release.apk`: **Сборка ARM64**. Оптимизирована для большинства современных смартфонов и планшетов (64-битные процессоры ARM). Обладает меньшим размером.
   - `app-armeabi-v7a-release.apk`: **Сборка ARMv7**. Для старых 32-битных Android-устройств.
   - `app-x86_64-release.apk`: **Сборка x86_64**. Для 64-битных эмуляторов Android (Android Studio, LDPlayer, BlueStacks) и устройств на базах процессоров Intel/AMD.
   - `app-x86-release.apk`: **Сборка x86**. Для 32-битных эмуляторов Android x86.
3. **Расчет SHA-256 (выполняется для каждой собираемой версии перед публикацией)**:
   - В PowerShell: `Get-FileHash -Algorithm SHA256 'app\build\outputs\apk\release\app-universal-release.apk'`
   - В Bash/Linux: `sha256sum app/build/outputs/apk/release/app-universal-release.apk`
