# Project Guidelines & Release Rules (Mirrly TG Proxy)

## 1. GitHub Release Notes Format & Verification Rule
При публикации релиза на GitHub для проекта Mirrly TG Proxy **ОБЯЗАТЕЛЬНО**:
1. **Первые две строчки релиза (Changelog Summary Preview)**: Первые 1–2 предложения релиза (после главного заголовка `#`) ДОЛЖНЫ содержать краткую выжимку ключевых изменений без использования спецсимволов заголовков (`#`). Данная выжимка автоматически извлекается парсером `UpdateChecker` и выводится в интерактивных уведомлениях Android (Rich Update Notifications).
2. **Публикация только Release APK**: На GitHub в артефакты релиза загружается **ТОЛЬКО** файл `app-release.apk` (публикация `app-debug.apk` запрещена).
3. **Контрольные отпечатки SHA-256**: Указывать в описании релиза контрольные отпечатки SHA-256 файла `app-release.apk` и ключа подписи (Keystore SHA-256).

Пример структуры начала релиза:
```markdown
# Mirrly TG Proxy — Релиз v1.0.5.1
В v1.0.5.1 реализована повышенная скорость буферизации до 2 МБ, защита от заторов сети и поддержка интерактивных уведомлений.

---
## 1. Контрольные отпечатки SHA-256
* **app-release.apk SHA-256**: `...`
* **SHA-256 подписи (Release)**: `97:73:5C:0A:20:70:7F:D4:E4:BD:93:A2:D8:48:CA:91:9A:C5:40:45:4A:62:16:E8:CC:7D:43:4F:1F:9F:0A:96`
```

## 2. Правило сборки и публикации APK (Release Only)
1. **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** пересобирать `debug` версию APK (`app-debug.apk`). Собираем **ТОЛЬКО** релизную версию APK (`release` APK / `./gradlew assembleRelease`).
2. **Публикация на GitHub**: В релизы на GitHub загружается и публикуется **ИСКЛЮЧИТЕЛЬНО** релизный файл `app-release.apk`.
